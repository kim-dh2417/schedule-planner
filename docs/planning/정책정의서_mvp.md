## 정책 항목

### 1. 일정 충돌 정책
- 같은 날짜에서 시간이 겹치면 충돌로 판단한다.
- 충돌 일정은 달력과 상세 드로어에서 경고 상태로 표시한다.
- 충돌이 있어도 저장은 가능하지만, 사용자에게 조정 필요를 명확히 보여준다.

### 2. 업무일지 기록 정책
- 업무일지는 날짜 단위로 작성한다.
- 한 날짜에는 하나의 업무일지를 기준으로 하되 수정은 자유롭게 가능하다.
- 업무일지는 최소한 한 줄 요약 또는 완료한 일 중 하나 이상이 있어야 저장할 수 있다.

### 3. 주간보고 정책
- 주간보고는 업무일지와 일정 데이터를 함께 참고해 자동 정리한다.
- 자동 생성된 주간보고는 최종 제출본이 아니라 초안으로 취급한다.
- 기록이 부족한 경우 빈 상태와 작성 유도 메시지를 우선 보여준다.

### 4. 저장 정책
- 일정 저장은 모달에서 완료한다.
- 업무일지 저장도 모달에서 완료한다.
- 저장 후에는 달력, 선택일 드로어, 상단 요약이 동시에 갱신된다.

### 5. 빈 상태 정책
- 일정이 없는 날짜는 빈 상태 메시지를 보여준다.
- 업무일지가 없는 날짜도 별도 빈 상태 메시지를 보여준다.
- 빈 상태에서는 다음 행동으로 이어지는 CTA를 함께 제공한다.

### 6. 알림 정책
- 브라우저 알림은 사용자가 명시적으로 권한을 허용한 경우에만 활성화한다.
- 알림은 일정별로 설정된 시점에 맞춰 브라우저/PC 알림으로 제공한다.
- 이메일 알림은 현재 범위에서 제외하고 차기 확장으로 둔다.

### 7. 기본값 및 요약 정책
- 새 일정 작성 시 마지막 사용 값과 선택일을 기본값으로 채운다.
- 저장 후에는 달력, 드로어, KPI가 동시에 갱신되어야 한다.
- 일정 밀도가 높은 날은 더보기 또는 기록 우선 안내를 제공한다.

### 8. 외부 연동 정책
- 외부 연동이 있더라도 내부 일정 CRUD와 업무일지가 기준 데이터여야 한다.
- 연동 실패 시 기능 중단이 아니라 경고와 재시도 안내를 우선한다.
- 휴일, 외부 캘린더, 이메일 알림 데이터는 보조 정보로만 사용한다.
- 민감한 토큰은 문서와 UI에 노출하지 않는다.
