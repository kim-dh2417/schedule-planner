## 목적
기능 추가, UI 변경, 데이터 구조 변경이 발생했을 때 반드시 다시 확인해야 하는 핵심 회귀 범위를 정리한다. 이후 기능이 늘어나면 이 목록을 우선 갱신한다.

## 핵심 회귀 범위
1. 일정 등록 흐름
   - Quick Draft 입력값 검증
   - 저장 성공 여부
   - 저장 후 목록/카드 동기화

2. 날짜 선택 흐름
   - 캘린더 선택 상태 유지
   - 선택 날짜의 상세 일정 갱신
   - 이전 날짜 데이터 잔존 여부

3. 충돌 표시
   - 같은 시간대 일정 충돌 표시
   - 색상/배지/문구 일관성
   - 충돌 해제 후 상태 초기화

4. 부하 상태
   - Team Pulse 계산 결과 반영
   - 과부하 강조 상태
   - 팀원 추가/삭제 시 재계산

5. 포커스 블록
   - 집중 시간 보호 여부
   - 일반 일정과의 시각적 구분
   - 겹치는 일정에 대한 경고

6. 반응형 레이아웃
   - 데스크톱 1300px 내외
   - 태블릿 768px 내외
   - 모바일 390px 내외
   - 스크롤/잘림/중첩 여부

7. 상태 처리
   - 로딩 상태
   - 빈 상태
   - 오류 상태
   - 저장 성공 상태

8. 디자인 시스템 연계
   - 버튼, 입력, 배지, 카드의 스타일 일관성
   - 타이포그래피 크기와 행간
   - 색상 토큰 변경 시 영향 범위

## 기능 추가 시 재점검 규칙
- 대시보드 상단 요약 영역 변경 시: KPI, Today Board, Quick Draft 동시 점검
- 일정 관련 기능 추가 시: 충돌, 부하, Focus Blocks 우선 점검
- 레이아웃 변경 시: 데스크톱과 모바일 둘 다 점검
- 데이터 모델 변경 시: 저장/조회/수정/삭제 흐름을 전부 재점검

## 회귀 우선순위
- P0: 일정 저장 실패, 데이터 유실, 화면 진입 불가
- P1: 충돌/부하/보호 시간 계산 오류
- P2: 레이아웃 깨짐, 정보 누락
- P3: 문구, 여백, 정렬과 같은 경미한 시각 문제

## 운영 메모
- 새로운 화면이 추가되면 각 화면별 회귀 목록을 별도로 분리한다.
- 실제 구현 전이므로 현재 목록은 `예상` 기준이며, 구현 후 확인 결과에 따라 갱신한다.
