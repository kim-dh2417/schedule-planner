## 목적
메인 대시보드에서 사용자가 실제로 수행하는 핵심 흐름을 단계별로 검증한다. 아직 구현되지 않은 부분은 `사전 점검`, `예상`, `구현 후 확인 필요`로 명시한다.

## 시나리오 1: 오늘 일정 확인 후 새 일정 추가
1. 사용자가 대시보드에 진입한다.
2. KPI 카드와 Today Board를 통해 오늘의 우선순위를 확인한다.
3. 캘린더에서 오늘 날짜를 선택한다.
4. Quick Draft에 일정 제목, 시간, 참여자, 유형을 입력한다.
5. 저장 버튼을 누른다.
6. Today Board와 캘린더에 새 일정이 즉시 반영되는지 확인한다.
7. Team Pulse의 부하 수치가 변경되었는지 확인한다. `구현 후 확인 필요`

## 시나리오 2: 특정 날짜의 일정과 충돌 상태 확인
1. 사용자가 캘린더에서 다음 주의 특정 날짜를 선택한다.
2. 해당 날짜 일정이 오른쪽 상세 영역 또는 하단 패널에 표시된다.
3. 시간 중복 일정이 있으면 충돌 배지가 표시되는지 확인한다.
4. 사용자가 충돌 경고를 보고 일정 시간을 조정한다.
5. 조정 후 충돌 표시가 해제되는지 확인한다.

## 시나리오 3: 팀 부하가 높은 상태를 기준으로 일정 재조정
1. 사용자가 Team Pulse를 본다.
2. 특정 팀원의 부하가 높게 표시된다.
3. 사용자가 해당 팀원 일정 중 일부를 다른 시간대로 옮길 후보를 확인한다.
4. 사용자가 집중 블록을 침범하지 않도록 시간을 다시 선택한다.
5. 팀 부하와 집중 블록 상태가 함께 안정화되는지 확인한다. `사전 점검`

## 시나리오 4: 집중 시간을 보호하면서 일정 추가
1. 사용자가 Focus Blocks 영역에서 보호 중인 시간대를 확인한다.
2. 사용자가 해당 시간과 겹치는 새 일정을 작성한다.
3. 시스템이 충돌 또는 경고를 표시한다.
4. 사용자가 다른 시간대로 변경하거나 저장을 취소한다.
5. 집중 블록 보호 규칙이 유지되는지 확인한다.

## 시나리오 5: 모바일 환경에서 대시보드 확인
1. 사용자가 모바일 폭으로 접속한다.
2. 카드가 세로 레이아웃으로 전환되는지 확인한다.
3. Today Board와 Quick Draft를 스크롤 없이 접근 가능한지 확인한다.
4. 터치 영역과 타이포그래피가 읽기 쉬운지 확인한다.
5. 주요 정보가 잘리지 않고 확인되는지 검증한다. `구현 후 확인 필요`

## 시나리오 6: 빈 데이터 상태에서 첫 사용
1. 사용자가 일정이 없는 계정으로 처음 진입한다.
2. 빈 상태 안내와 시작 CTA를 확인한다.
3. 사용자가 Quick Draft로 첫 일정을 등록한다.
4. 이후 캘린더와 Today Board가 초기화된 빈 상태에서 데이터 상태로 전환되는지 본다.

## 시나리오 검증 포인트
- 데이터가 없을 때도 화면이 빈 껍데기처럼 보이지 않아야 한다.
- 충돌, 과부하, 보호 시간대 같은 상태는 문구와 시각적 구분이 함께 있어야 한다.
- 시나리오 흐름 중 사용자가 길을 잃지 않도록 CTA가 명확해야 한다.
