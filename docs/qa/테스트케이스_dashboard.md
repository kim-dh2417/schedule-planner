## 목적
메인 대시보드의 핵심 기능인 일정 조회, 일정 생성, 날짜 선택, 팀 부하 확인, 집중 블록 확인, 반응형 동작을 검증하기 위한 테스트케이스를 정의한다. 아직 실제 구현과 테스트가 완료되지 않은 항목은 `구현 후 확인 필요`로 표기한다.

## 테스트케이스 목록
| ID | 목적 | 사전조건 | 입력/절차 | 기대결과 |
|---|---|---|---|---|
| TC-DASH-001 | 대시보드 기본 화면이 정상 표시되는지 확인 | 앱 실행 완료, 초기 데이터 로드 가능 | 메인 페이지 진입 | Hero, KPI 카드, 캘린더, Today Board, Quick Draft, Team Pulse, Focus Blocks가 노출된다. `구현 후 확인 필요` 항목은 비어 있지 않게 예상 상태로 표시된다. |
| TC-DASH-002 | 날짜 선택 시 해당 날짜 일정이 갱신되는지 확인 | 일정 데이터가 2일 이상 존재 | 캘린더에서 다른 날짜 선택 | 선택한 날짜의 일정 목록과 요약 정보가 갱신된다. 이전 날짜 정보가 남아 있지 않는다. |
| TC-DASH-003 | 오늘 일정이 Today Board에 우선 표시되는지 확인 | 오늘 일정 1건 이상 존재 | 대시보드 진입 | 오늘 일정이 상단 또는 강조 영역에 표시되고, 시간순으로 정렬된다. |
| TC-DASH-004 | Quick Draft로 새 일정을 저장할 수 있는지 확인 | 입력 가능한 상태, 저장 대상 데이터소스 연결 예정 | 제목, 날짜, 시간, 참여자, 유형 입력 후 저장 | 일정이 저장되고 캘린더와 Today Board가 갱신된다. 저장 완료 토스트 또는 피드백이 표시된다. `구현 후 확인 필요` |
| TC-DASH-005 | 일정 충돌이 시각적으로 표시되는지 확인 | 시간 중복 일정 2건 준비 | 겹치는 시간대 일정 등록 또는 조회 | 충돌 상태가 색상, 배지, 경고 문구 중 하나 이상으로 드러난다. 충돌 정보가 숨겨지지 않는다. |
| TC-DASH-006 | Team Pulse가 팀원 부하를 적절히 보여주는지 확인 | 팀원별 일정 수 또는 시간 합산 데이터 준비 | Team Pulse 영역 확인 | 팀원별 부하가 비교 가능하게 표시된다. 과부하 상태는 별도 강조된다. |
| TC-DASH-007 | Focus Blocks가 집중 시간 우선순위를 유지하는지 확인 | 집중 블록 데이터 존재 | Focus Blocks 영역 확인 | 집중 블록이 일반 일정과 구분되어 보이고, 우선순위 또는 보호 상태가 표현된다. |
| TC-DASH-008 | 반응형 레이아웃이 모바일에서 깨지지 않는지 확인 | 모바일 뷰포트 준비 | 폭을 줄여 모바일 너비로 확인 | 주요 패널이 세로로 재배치되고 가독성이 유지된다. 가로 스크롤이 과도하게 발생하지 않는다. `구현 후 확인 필요` |
| TC-DASH-009 | 빈 상태가 정보 손실 없이 표시되는지 확인 | 일정 데이터가 없는 상태 | 빈 계정 또는 빈 날짜 진입 | 빈 상태 문구, 안내, CTA가 보여야 한다. 단순 공백만 보여서는 안 된다. |
| TC-DASH-010 | 수정/삭제 후 UI가 즉시 반영되는지 확인 | 기존 일정 1건 존재 | 일정 수정 또는 삭제 | 목록과 요약 카드가 최신 상태로 갱신된다. 캐시 잔존으로 이전 값이 남지 않는다. |

## 사전 점검 기준
- API 응답이 정상인지 먼저 확인한다.
- 캘린더, Today Board, Quick Draft, Team Pulse, Focus Blocks가 같은 데이터 기준을 공유하는지 확인한다.
- 색상만으로 상태를 구분하지 않고 텍스트/아이콘도 함께 제공하는지 확인한다.
- 반응형 검증은 데스크톱, 태블릿, 모바일의 최소 3개 폭에서 점검한다.

## 참고
- 본 테스트케이스는 메인 대시보드 기준이다.
- 로그인, 설정, 별도 상세 화면이 추가되면 각 화면별 테스트케이스를 별도 생성한다.
