## 목적
출시 전 수동 점검 시 기능, 디자인, 반응형, 상태별로 확인해야 할 항목을 정리한다. 미구현 또는 미검증 항목은 `구현 후 확인 필요`로 남긴다.

## 기능 점검
- [ ] 메인 대시보드 진입 시 주요 섹션이 모두 표시되는가
- [ ] 캘린더 날짜 선택 시 상세 정보가 갱신되는가
- [ ] Quick Draft 저장이 정상 동작하는가 `구현 후 확인 필요`
- [ ] 일정 수정/삭제 후 화면 반영이 즉시 이루어지는가
- [ ] Team Pulse가 팀원별 부하를 비교 가능하게 보여주는가
- [ ] Focus Blocks가 일반 일정과 구분되는가

## 디자인 점검
- [ ] 헤더, KPI 카드, 캘린더, Today Board, Quick Draft, Team Pulse, Focus Blocks의 시각 위계가 분명한가
- [ ] 상태 색상이 너무 많지 않고 일관되게 사용되는가
- [ ] 여백과 정렬이 섹션별로 안정적인가
- [ ] 빈 상태와 경고 상태의 문구가 UI 톤과 맞는가
- [ ] 버튼과 입력 필드가 디자인 시스템과 일치하는가 `구현 후 확인 필요`

## 반응형 점검
- [ ] 데스크톱에서 한 화면에 핵심 정보가 읽히는가
- [ ] 태블릿에서 2열 또는 축약 레이아웃이 무너지지 않는가
- [ ] 모바일에서 세로 스택으로 자연스럽게 전환되는가
- [ ] 가로 스크롤 없이 주요 기능이 접근 가능한가
- [ ] 터치 대상 크기가 너무 작지 않은가

## 상태 점검
- [ ] 빈 일정 상태가 명확히 안내되는가
- [ ] 충돌 일정이 눈에 띄게 표시되는가
- [ ] 과부하 팀원이 강조되는가
- [ ] 집중 블록이 보호 상태로 표현되는가
- [ ] 로딩 중, 오류, 저장 성공 상태가 구분되는가 `구현 후 확인 필요`

## 사전 점검
- [ ] API 응답 형식이 문서와 일치하는가
- [ ] 시간대 및 날짜 형식이 로컬 기준으로 일관적인가
- [ ] 접근성 대비가 충분한가
- [ ] 텍스트가 버튼이나 카드 영역 밖으로 잘리지 않는가

## 출시 전 확인 메모
- 실제 구현 전이므로 일부 항목은 `예상` 기준으로 남겨 둔다.
- 최종 승인 전에는 사용성 테스트 1회 이상을 권장한다.
