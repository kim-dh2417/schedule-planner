## 목적
이 문서는 `기획안_mvp.md`, `기능명세서_mvp.md`, `화면흐름도_dashboard.md`, `정책정의서_mvp.md`를 기준으로, 일정관리 앱의 메인 화면을 `달력 중심`으로 재설계하기 위한 UI 시안을 정의한다. 핵심은 달력이 화면의 주인공이고, 일정 상세와 편집은 보조 레이어에서 열리는 구조다.

## 디자인 원칙
- 달력은 화면 면적의 대부분을 차지한다.
- 정보는 항상 펼쳐두기보다, 필요한 순간에 드로어와 모달로 꺼낸다.
- 상단 KPI는 운영 상태를 요약하는 얇은 띠로 축소한다.
- Team Pulse와 Focus Blocks는 보조 행동으로 진입한다.
- 모바일에서는 달력 우선, 상세는 바텀시트로 전환한다.

## 화면 위계
1. Hero 영역
1. KPI 요약 띠
1. 월간 캘린더 메인
1. 우측 선택일 드로어
1. 일정 추가/수정 모달
1. Team Pulse 보조 패널 또는 팝업
1. Focus Blocks 보조 패널 또는 탭

## 비주얼 방향
- 전체 톤은 따뜻한 에디토리얼 업무 도구 느낌으로 간다.
- 배경은 은은한 그라데이션과 부드러운 면 분할을 사용한다.
- 달력 셀은 가볍고 정돈된 카드로 보이게 한다.
- 선택일과 충돌 상태는 색보다 구조와 강조선으로 먼저 구분한다.
- 버튼은 많지 않게 두고, 주요 동작만 선명하게 노출한다.

## 화면 구성
### Hero
- 앱의 목적과 현재 월을 짧게 보여준다.
- 우측에는 `새 일정 작성` 같은 강한 CTA 1개만 둔다.

### KPI 띠
- `오늘 일정`, `집중 블록`, `회의 비중`, `완료율`만 압축 노출한다.
- 카드 높이를 낮춰 달력의 시각적 우선순위를 방해하지 않는다.

### 캘린더
- 7열 월간 그리드가 화면의 메인 면적을 차지한다.
- 날짜 셀 안에는 이벤트를 2개까지만 요약 노출한다.
- `Today`, `충돌`, `비어 있음` 상태를 셀 레벨에서 즉시 구분한다.
- 선택된 날짜는 전체 셀 배경과 테두리로 강조한다.

### 우측 드로어
- 날짜 클릭 시 우측 드로어가 열리고 선택일의 일정 목록과 상세를 보여준다.
- 드로어 상단에는 날짜, 일정 개수, 충돌 여부를 보여준다.
- 드로어 안에서 바로 편집 모달로 진입할 수 있다.

### 일정 모달
- 일정 추가와 수정은 동일한 폼 구조를 사용한다.
- 시간, 참여자, 유형, 상태, 메모를 한 화면에서 입력한다.
- 저장 버튼과 삭제 버튼은 마지막 액션으로 분리한다.

### Team Pulse / Focus Blocks
- 상단 액션 또는 보조 탭에서 열리는 레이어로 두고, 기본 화면에서는 축약한다.
- Team Pulse는 리소스 상태를, Focus Blocks는 보호 시간대를 보여준다.

## 상태 표현
- 기본: 정보가 정상적으로 보이는 상태
- 빈 상태: 선택한 날짜에 일정이 없을 때
- 충돌 상태: 같은 날짜에 시간이 겹칠 때
- 선택 상태: 날짜 셀과 드로어가 함께 하이라이트될 때
- 편집 상태: 일정 모달이 기존 값을 채운 상태로 열릴 때

## 모바일
- 모바일에서는 캘린더를 1순위로 유지한다.
- 드로어는 전체 화면 오버레이 또는 바텀시트로 전환한다.
- KPI는 2열 또는 1열 축약 카드로 줄인다.
- 보조 패널은 탭 또는 접이식 레이어로 처리한다.

## Handoff
- 달력 셀 클릭 -> 선택일 드로어 오픈
- 드로어의 일정 클릭 -> 일정 모달 오픈
- `새 일정 작성` 클릭 -> 일정 추가 모달 오픈
- `Team Pulse`, `Focus Blocks` -> 보조 레이어 오픈
