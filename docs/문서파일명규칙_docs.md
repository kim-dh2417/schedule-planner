# 문서 파일명 규칙

## 기본 규칙

- 문서주도 개발을 기본 원칙으로 삼는다.
- 기획, 디자인, 개발, QA 작업은 가능한 한 문서를 먼저 만들거나 기존 문서를 갱신한 뒤 진행한다.
- 파일명은 `<문서종류>_<주제>.md` 패턴을 기본으로 사용한다.
- 문서종류는 한글로 작성한다.
- 주제는 영어 슬러그를 사용한다.
- 구분자는 `_`를 사용한다.
- 문서 폴더 경로가 이미 프로젝트를 나타내므로 파일명에는 프로젝트명을 반복하지 않는 것을 기본으로 한다.

## 주제 작성 규칙

- 주제는 짧고 재사용 가능한 영어 슬러그로 작성한다.
- 예시:
- `mvp`
- `dashboard`
- `calendar`
- `onboarding`
- `scheduling-rules`

## 문서주도 개발 흐름

- 기획: 요구사항과 정책을 문서로 고정한다.
- 디자인: 기획 문서를 읽고 화면 구조와 상태를 문서화한다.
- 개발: 기획/디자인 문서를 읽고 구현 범위와 변경 내역을 문서화한 뒤 코드 작업을 진행한다.
- QA: 기획/디자인/개발 문서를 기준으로 검증 시나리오와 결과를 문서화한다.
- 문서가 없거나 불완전하면 새 문서를 만들거나 기존 문서를 보완한 뒤 다음 역할로 넘긴다.

## 피해야 할 패턴

- 의미 없는 파일명
- 공백 포함 파일명
- `final`, `new`, `v2`, `last` 같은 의미 없는 접미사
- 날짜만 있는 파일명
- 같은 의미의 영문/한글 접두어를 함께 쓰는 중복 표현 예: `design_디자인시안_dashboard.md`
